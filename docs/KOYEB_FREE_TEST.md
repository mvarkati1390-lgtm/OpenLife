# راه‌اندازی آزمایشی OpenLife روی Koyeb (رایگان)

این راهنما فقط برای نمونهٔ آزمایشی است، نه سرور پایدار بازی.

## محدودیت‌های مهم پلن رایگان
- یک سرویس وب رایگان با ۵۱۲ مگابایت RAM و ۲ گیگابایت SSD موقت ارائه می‌شود.
- سرویس پس از یک ساعت بدون ترافیک به صفر مقیاس می‌شود.
- Volume یا فضای ذخیره‌سازی دائمی روی پلن رایگان وجود ندارد.
- فایل SQLite در `/tmp/openlife.db` قرار می‌گیرد؛ با راه‌اندازی مجدد یا جایگزینی نمونه ممکن است حساب‌ها، پروفایل‌ها و داده‌های بازی از بین بروند.
- برای اطلاعات واقعی بازیکنان یا استفادهٔ عمومی، تا زمان افزودن پایگاه دادهٔ پایدار از این نسخه استفاده نکنید.

## مراحل استقرار
1. در Koyeb یک Web Service جدید بسازید و GitHub را به Koyeb وصل کنید.
2. مخزن `mvarkati1390-lgtm/OpenLife` و شاخه `koyeb-free-test` را انتخاب کنید.
3. Builder را روی Dockerfile قرار دهید و مسیر Dockerfile را `server/Dockerfile` بگذارید. Work directory ریشهٔ مخزن باشد.
4. پورت `3000` را به‌صورت HTTP در معرض اینترنت قرار دهید و مسیر سلامت را `/health` تنظیم کنید.
5. متغیرهای محیطی زیر را در داشبورد Koyeb تعریف کنید:
   - `NODE_ENV=production`
   - `PORT=3000`
   - `DB_FILE=/tmp/openlife.db`
   - `JWT_SECRET`: یک مقدار تصادفی محرمانه با حداقل ۳۲ کاراکتر
   - `OWNER_USERNAME`: نام کاربری دلخواه برای مالک اولیه
   - `OWNER_PASSWORD`: یک رمز قوی و منحصربه‌فرد، حداقل ۱۰ کاراکتر
   - `CORS_ORIGIN=https://mvarkati1390-lgtm.github.io`
6. سرویس را Deploy کنید. پس از موفقیت، نشانی HTTPS سرویس را باز کنید و `/health` را بررسی کنید؛ پاسخ باید شامل `ok: true` باشد.

## امنیت
- رمزها و کلیدهای واقعی را در GitHub یا چت قرار ندهید؛ فقط در بخش Environment Variables داشبورد Koyeb وارد کنید.
- از رمز مشترک با حساب‌های دیگر استفاده نکنید.
- تا پیش از پیکربندی ذخیره‌سازی پایدار و آزمون امنیتی، سرور را برای داده‌های مهم یا کاربران واقعی معرفی نکنید.
- ایجاد فایل‌های این شاخه به معنی Deploy شدن سرویس نیست. اتصال GitHub به Koyeb و فشردن Deploy در داشبورد هنوز باید انجام شود.
